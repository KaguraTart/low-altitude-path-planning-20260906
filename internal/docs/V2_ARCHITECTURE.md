# v2 架构与实现

文档日期：2026-10-30。

本文件描述内部实现。对外字段、规则、错误码和调用示例见 [`../../docs/API.md`](../../docs/API.md)。OpenAPI 从 `server.app:app` 的类型模型生成。

## 1. 分层

服务仅提供 `/api/v2`，使用 `uav_planner/v2` 和 `server/v2.py`。公开 SDK 为 `register_scene/plan_single_v2/plan_batch_v2/validate_route_v2/convert_coordinates`。HTTP handler 调用同一 SDK。CPU 规划在线程中运行。

| 文件 / 层 | 责任 |
|------|------|
| `models.py` | 输入与输出模型；数值、时间、WKT 和引用校验 |
| `coordinates.py` | WGS84 与 AEQD 转换；EG/MSL/AGL/ELLIPSOID/QNE/QNH 高度换算 |
| `scene.py` | 场景编译、空间索引、体积与时间裁剪、场数据查询、航路包含检查 |
| `rules.py` | 20 类规则解析、引用检查、搜索筛选、连续规则检查与报告 |
| `motion.py` | 直线、爬降、圆弧、悬停、原地偏航、加减速时间律与采样 |
| `native.py`、`native/` | C++17 搜索、时间预约、连续碰撞与独立运动学验证 |
| `engine.py` | 场景登记、任务排序、候选路径、调度、最终验证与输出 |
| `profiles.py` | DJI Mini 4 Pro 默认配置与机型解析 |
| `server/v2.py` | HTTP 路由、作业表、示例、能力查询与版本 |

`/docs` 是 Swagger UI。它读取 `/openapi.json`。发布镜像同时包含代码、`docs/API.md` 和规范快照。

## 2. 场景、空间与高度

`SceneRegistry` 用规范化场景 JSON 的 SHA-256 标识场景版本。相同输入复用不可变的编译结果。缓存包含场景几何、缓冲与查询索引，不包含任务答案。场景按顺序编译，并单独报告耗时。

场景对象、WKT 顶点、数据格、网格节点和估算存储不设固定上限。登记表不设固定数量或合计存储上限，也不自动淘汰场景。`capabilities` 保留资源上限字段；null 表示未设置固定上限。

外部 WKT 的 x/y 为经度/纬度。内部 x/y 为 AEQD 东/北坐标，单位为米。内部 z 为 `EG-origin_alt_ellipsoid`。`max_radius_m` 指定场景覆盖半径，默认 50000 m，可设置更大的正数。障碍检查使用投影后的原始几何。净空包含飞机半径、半高与安全裕度。

EG/ELLIPSOID 直接使用椭球高。MSL 按 h=H+N 转为 EG，并声明水准面差及来源。AGL 加上地形 EG 高度。QNE/QNH 加上对应位置和时间内唯一的 EG 修正值。重叠有效地形格采用较高 EG 高度。

数据集和单元格的有效期共同确定数据可用时间。WKT 单元格采用地理足迹和 EG 高度。bounds 单元格采用局部米制三维边界。外部占用网格使用 `LOCAL_AEQD`，支持稀疏索引、索引范围和显式边界格。

## 3. 航路、规则与搜索

默认模式为 `strict`。`widthMeters` 是航路全宽，编译时除以二。中心线 Z 是参考高度；`minAltitude/maxAltitude` 和高度基准确定垂直范围。参考高度受阻时，搜索按代价和稳定顺序尝试其他可用高度层。

严格模式检查完整运动段的扫掠体。扫掠体需位于有效航路或授权起终点接驳体内。接驳关联由 `airway_ids` 指定。接驳用于进入或离开航路。航路断连时返回规划失败。

`prefer` 允许航路外飞行，航路外基础距离代价为航路内的 2 倍。`free` 在合法空域中搜索。三种模式均执行障碍、机型与选定规则检查。搜索优先尝试安全直连边，再建立航路与绕行锚点的稀疏图；需要时使用场景内三维网格。最终候选按原始几何复核。

20 类规则通过 `RULE_KEYS` 解析。编译时检查引用和必要数据。搜索与验证使用规则生效时间、空间范围和整段运动。WEATHER、SIGNAL 和 PRIORITY 使用上游提供的天气、信号、风险与噪声数据。

默认不限制搜索次数。`time_budget_s` 省略或为 null 时持续计算；指定正有限秒数时，在该时限内计算。`horizon_s` 是业务飞行时域，默认 3600 秒，可设置更大的正数。搜索结束仍未找到路线时返回 `SEARCH_NOT_FOUND`。

## 4. 运动学与连续调度

运动构建输出 `line/arc/climb/descent/hover/yaw` 原语。直线和圆弧采用梯形或三角形速度过程。转弯检查半径、偏航率、切向加速度和向心加速度。零半径转向先停车，并计入原地偏航时间。业务悬停使用航点标记，并执行 HOVER 规则。

原生验证器检查原语几何、阶段积分、速度、爬降率、转弯、加速度及连续性。WKT 和 `vertex_times_s` 是运动的采样视图。解析原语保留局部坐标、时间律和转角，用于重建真实运动。采样和导出顶点不设固定数量上限。

任务按优先级、最晚到达和 ID 稳定排序。批量调度计算不安全的出发时间区间，再选择可用时间。到达窗、航点窗、TIME 日历、续航和场景时域共同约束调度。当前窗口受阻时，搜索继续检查后续窗口。上游动态轨迹作为已有预约保留。

连续冲突检查使用分段时空轨迹与空间索引，覆盖边交换、交叉和悬停。水平与垂直间隔同时不足时判为冲突。解析运动生成有误差界的弦覆盖，并保守扩大检查间隔。调度后独立复核几何、规则、动态轨迹和机间间隔。

有动态轨迹时，安全时间区间搜索使用定时运动宏边。宏边保留折线与时间，并在合法停车点连接。等待执行悬停与速度规则。调度后再次检查已有预约。

## 5. 返航、输出与运行错误

所有数字时间相对 `Scene.time_origin`。绝对任务时间、规则时间和数据有效期使用带时区时间。RTL 使用上游提交的电量、剩余航程、剩余飞行时间和 home。触发后生成返航路线，检查返航高度与剩余飞行能力，并返回 `action=return_to_home`。平台负责状态监测、飞控执行和后续重规划。

每个任务返回一个结果。路线不可行时返回 failed。调用方设置的计算时限到期时返回 timeout。输出包括场景版本、端点、WKT、顶点时间、运动原语、关键点、验证结果和规则报告。保存完整输入与输出，以便复核。

服务捕获到内存分配失败时，返回 HTTP 503、`RESOURCE_EXHAUSTED`。异步作业以 failed 和同名错误码记录失败。系统 OOM 直接终止进程时，连接可能断开。Docker 记录 OOM 并按重启策略重启服务。

## 6. 验收与运维

测试目录见 [`../../tests/README.md`](../../tests/README.md)。`api/` 检查 HTTP 契约，`planning/` 检查规划约束，`native/` 检查计算核，`integration/` 检查完整调用和数据归档。

冻结输入位于 `input/engine_contract_20261029`，种子为 20261016，manifest 记录 SHA-256。strict/mixed/free 三套各有 1000 个任务和已知可行参考调度。mixed 覆盖全部 20 类规则，并用反事实用例检查规则效果。

2026-10-16 的历史验收使用 8 CPU / 8 GiB。三套各运行 10 轮，30/30 轮通过。每轮均返回 1000 条有效路线，冲突为 0。strict/mixed/free 最大完整 HTTP/JSON 耗时为 1.454/4.541/1.191 秒。服务 cgroup memory.peak 为 281.72 MiB，进程 VmHWM 为 327.51 MiB，OOM 为 0。完整记录见 [`../reports/v2-20261016/PERFORMANCE.md`](../reports/v2-20261016/PERFORMANCE.md)。

正式服务保持 2 CPU / 2 GiB。后台作业使用 1 个执行线程，其他作业排队等待。默认不限制队列数量、历史数量或结果存储字节数，也不自动淘汰作业。

场景和作业保存在单个服务进程中，重启后清空。替换容器前暂停新提交，并排空作业。重启后重新注册场景。正式端口为 18000，候选端口为 18001。部署与回滚步骤见 [`DEPLOYMENT.md`](DEPLOYMENT.md)。
