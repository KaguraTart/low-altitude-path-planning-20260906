# v2 架构与实现边界

本文件描述内部实现。外部字段、全部规则、错误与调用示例仅在 [`../../docs/API.md`](../../docs/API.md) 维护，OpenAPI 从 `server.app:app` 的实际类型模型生成。

## 1. 分层与版本隔离

v1 的 `uav_planner.api`、既有 `src/` 算法、`server.schemas` 和 `/api/v1` 契约保留。v2 新增 `uav_planner/v2` 与 `server/v2.py`，公开 SDK 为 `register_scene/plan_single_v2/plan_batch_v2/validate_route_v2/convert_coordinates`。HTTP handler 直接调用同一 SDK 实现；CPU 规划不阻塞 ASGI 事件循环。

| 文件 / 层 | 责任 |
|------|------|
| `models.py` | 拒绝额外字段的 Pydantic 模型，有限数值、带时区时间、WKT、所有请求/响应约束 |
| `coordinates.py` | always_xy WGS84↔AEQD；显式 MSL/AGL/ELLIPSOID/QNE/QNH 高度证据 |
| `scene.py` | 编译资源、空间索引、体积/时间裁剪、地形与场查询、航路/接驳包含、硬几何验证 |
| `rules.py` | ALL20 精确键注册表、引用检查、搜索限制、连续规则检查、报告 |
| `motion.py` | 直线、爬降、圆弧、悬停、原地偏航；加减速时间律与有误差界的采样视图 |
| `native.py`、`native/` | 数组边界、C++17 搜索、时间预约、连续碰撞与独立运动学证书 |
| `engine.py` | 场景版本注册、任务顺序、候选路径、运动构建、调度、最终验证和 JSON 结果 |
| `profiles.py` | DJI Mini 4 Pro 工程默认值及机型解析 |
| `server/v2.py` | typed `/api/v2` 路由、场景选择、作业表、examples、capabilities/version |

OpenAPI 描述模型及端点；`/docs` 是其 Swagger UI 包装。`docs/API.md` 补充业务语义和完整示例。发布同时打包代码、Markdown 和模型生成的规范快照，防止镜像与文档错版。

## 2. 场景、空间与高度

`SceneRegistry` 以模型规范 JSON 的 SHA-256 标识场景版本，复用不可变 `CompiledScene`，最多保留 8 场景、合计 1 GiB 估算存储并按最近使用淘汰，单场景估算上限 512 MiB，编译串行执行。缓存只包含场景编译、缓冲和空间查询等结构，不包含任务答案。修改输入或数据版本会产生新场景；注册编译耗时独立报告。

外部 WKT 的 x/y 是经度/纬度，内部 x/y 是原点 AEQD 东/北米；z 为 `MSL-origin_alt_msl`。最大场景投影半径 50 km，越界拒绝。体积足迹投影后使用原始多边形，不能把障碍简化成会放过边缘的点检查；净空以飞机半径、半高和安全裕度对障碍扩张、对授权航路收缩。

MSL 直接解释；ELLIPSOID 减声明的 geoid separation；AGL 通过地形空间场回调或声明平地海拔换算；QNE/QNH 通过给定时空覆盖中唯一的修正转换。没有证据就返回明确错误。terrain 数据先于资源编译，回调按位置和数据/格子有效时间获取海拔；重叠有效地形取较高值。相关数据未覆盖、过期或 nodata 不放行。

规则空间场的 dataset 与 cell 有效期共同裁剪。WKT 单元格以地理足迹和 MSL 高度界限表达，bounds 单元格直接采用局部米制三维边界。网格导入当前仅 `LOCAL_AEQD`，支持稀疏索引、闭区间索引范围和显式边界占用格；不宣称支持 WGS84 网格。

## 3. 航路、规则与搜索

`strict` 默认启用。航路全宽 `widthMeters` 在编译时除以二，中心线 Z 只是三维参考，硬垂直边界来自 min/max 和高度基准；参考高度受阻时，按距起点高度的代价和固定排序尝试高度带内的替代层。单段扫掠体必须被有效航路与授权起终点接驳的并集完整覆盖；接驳只允许真实端点连接到首次/末次航路位置，且按 `airway_ids` 限定目标航路。中途不能借接驳抄近路，无法搜索时不回退自由模式。

`prefer` 可出航路，候选图在航路外使用 2 倍基础距离代价；`free` 不要求航路包含。两者仍检查所有基本安全、性能和所选规则。直接安全边优先尝试；需要绕行时建立带航路、障碍绕行锚点的稀疏近邻图，必要时在非 strict 模式下使用有界 3D 网格搜索。最终候选以原始几何再次检查，栅格不能绕过连续边检查。

所有 20 类规则都经过 `RULE_KEYS` 闭集解析，资源与必要数据值在编译时核验；任务 rule_ids 可选择规则，但不能取消基本障碍、机型和 strict 包含检查。规则生效时间、资源空间范围、整段几何与高度求交，避免只用端点或出发时刻判断完整飞行。WEATHER/SIGNAL 的观测和预报由上游提供；服务不会联网获取实时环境。PRIORITY 使用版本化风险/噪声场计算路线代价，数据缺口也是不可行。

## 4. 运动学与连续时空调度

候选折线经过运动构建，输出解析 `line/arc/climb/descent/hover/yaw` 原语。直线和圆弧带梯形/三角形速度阶段；转弯检查最小半径、偏航率及切向与向心加速度组合。零半径转向停车并计算实际原地偏航时间。业务悬停需显式标记且满足 HOVER；速度规则区别物理起停阶段与巡航，不能强迫从静止瞬间达到最小巡航速度。

C++ 原生验证器独立检查原语几何、阶段积分、峰值速度、爬降率、转弯、加速度和时空/速度连续性。WKT 和 vertex_times 是精确运动的有限误差折线视图，公开原语保留局部米制坐标、相对场景零点时间、速度阶段和有符号转角，方便独立重建证书。

任务按优先级、最晚到达和 ID 稳定排序。批量调度以连续时间预约计算不允许的出发延迟区间，跳到安全时间；业务到达窗、航点窗、TIME 日历窗口、续航和场景时域约束可选延迟；首个日历窗口被预约阻断时，保留已有预约重试后续开放窗口。上游 dynamic_obstacles 先固定保留，即使上游轨迹相互冲突也不能将其移除。待起飞前的地面等待不占用空中航迹；实际轨迹起飞后才开始预约。

连续冲突使用分段线性时空轨迹与空间索引；只有水平和垂直间隔同时不足才构成冲突，包含边交换和交叉。解析运动先生成有误差界的弦覆盖，并对安全间隔保守加量。调度完成后重新做独立几何、规则、动态与机间冲突检查；违反约束的结果标为失败，不能返回 planned 掩盖残余冲突。

存在上游动态轨迹时，生产流程使用安全时间区间搜索，将完整定时运动划为仅在既有零速度状态连接的宏边。宏边保留真实折线及其时间，等待只允许发生在合法停车点；后续批量预约仍复核所有观测轨迹。当前搜索采用有界候选图及分辨率，不提供一般场景的完备性保证；未找到候选明确返回 SEARCH_NOT_FOUND。

## 5. 返航、时间与输出

所有数字时间相对必填 `Scene.time_origin`，绝对任务/规则/数据时间含时区。当前状态由平台提供；RTL 开启低电触发时要求电量、剩余航程/续航和 home。达到阈值后本次目标改为 home 并规划满足返航高度的路线，检查当前剩余资源预算；输出 action=return_to_home。服务不持续监听状态、不下发飞控命令，平台负责持续储备监测、执行和后续状态变化时的重规划。

每个请求任务都有结果；输入合法但无路、最终约束失败或预算耗尽返回逐任务 failed/timeout。HTTP 200 不等于全成功，异步 succeeded 不等于每条 planned。输出包括场景版本、原始/生效端点、WKT+时间、原语、关键点、验证与规则报告；下游应保存整份结果及原始输入用于追溯。

## 6. 验收与运维边界

冻结输入位于 `input/v2_benchmarks`，manifest 使用 SHA-256，种子 20261016；基准在优化前建立独立构造参考调度，三套各 1000 任务均有实际冲突和已知可行窗口。mixed 包含全部 20 类规则、转弯/爬升/航点、危险环境区域及真实低电返航，另用反事实见证检查规则确实改变可行性或代价。完整定义以冻结输入和 runner 为准。

硬门槛为场景预注册后，在 8 CPU / 8 GB 上三套各 10 轮，每轮 1000 条全部成功并独立验证，完整 HTTP/JSON ≤10 秒。验证从导出的原语独立重建运动学证书、检查端点/窗/规则和连续间隔，不用生产调度输出自证安全。报告保存每轮耗时、哈希、成功数、验证数、冲突、指标和资源证据。初轮宿主机 SDK 诊断 strict/mixed/free 为 1.514/4.623/1.211 秒且全部成功；Docker 十轮 HTTP 最终结果仍为**待验证**。

场景和 v1/v2 两套作业表均在进程内存，单进程部署；重启前排空两版本并暂停新提交，重启后平台重新注册场景。正式回环端口保持 18000，候选 18001，镜像按 Git SHA 选择且文档同行。发布、回滚和原 v1 镜像基线详见 [`DEPLOYMENT.md`](DEPLOYMENT.md)。
